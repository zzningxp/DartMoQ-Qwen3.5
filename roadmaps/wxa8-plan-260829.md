# WxA8 路线规划（2026-08-29）

> WxA16 阶段已进入维护态（混合 bit 权重 + fp16 激活 + fp16 Tensor Core 计算）。
> 本文件规划 **WxA8** 新路线：激活量化为 INT8，矩阵运算走 INT8 Tensor Core（INT32 累加），
> 反量化回 FP16 后做非线性。目标：在 ppl 可控前提下进一步提升推理速度。

---

## 一、技术方案

### 数据流（一层 MoE 为例）

```
上一层输出 (FP16)
    ↓
[激活量化]  per-token 对称量化 → INT8  + scale (FP16)
    ↓
[矩阵乘法]  INT8 激活 × INT8 权重（混合 bit 反量化到 INT8）→ INT32 累加
    ↓
[反量化]   INT32 × scale 乘积 → FP16
    ↓
[非线性]    SiLU / MoE gate 等（FP16）
    ↓
[下一层]
```

### 核心要点

- **A8 = 参与矩阵运算的激活输入是 8-bit**（不是输出 8-bit，也不是激活函数 8-bit）
- 矩阵乘累加器始终是 **INT32**（硬件标准，防止溢出）
- 反量化后回到 **FP16**，所有非线性、归一化、路由都在 FP16 下做
- 权重仍然是混合 bit（1/2/4bit），但 kernel 内先反量化到 **INT8** 再参与矩阵乘
- Triton 原生支持 `tl.dot(int8, int8, out_dtype=int32)`，走 IMMA/WGMMA 指令

### 为什么是 WxA8（先不做 WxA4）

| 维度 | WxA8 | WxA4（int4 计算） |
|---|---|---|
| Triton 支持 | ✅ `tl.dot(int8,int8) → int32` 成熟 | ❌ 无 WGMMA int4，需外部库或 inline PTX |
| 理论吞吐 | ~4x FP16（SM120） | ~8x FP16（SM120） |
| ppl 退化 | 小（0.1-0.3 ppl） | 中（0.5-1.0 ppl，需更精细量化策略） |
| 工程难度 | 中（5-10 人天） | 高（20-40 人天，Machete 库或 CUTLASS） |
| 基础设施复用 | 高（量化框架、MoE 调度全部复用） | 中（需要重新处理 int4 packing） |

**结论**：WxA8 是最务实的下一步。Triton 原生支持，工程可控，精度风险低。
等 WxA8 跑通验证后，再考虑 WxA4（上 Machete 库或 CUTLASS）。

## 二、量化方案

### 激活量化

- **方式**：per-token 对称量化（per-token symmetric）
- **公式**：`x_int8 = round(x_fp16 / scale)`，`scale = max(abs(x)) / 127`
- **精度**：per-token 比 per-channel 精度更好（每个 token 独立 scale）
- **计算位置**：在 MoE forward 入口处做，紧接矩阵乘法之前（减少量化后数据的搬运距离）

### 权重量化

- 权重仍然是**混合 bit 分组量化**格式（与 WxA16 相同的 packing 方式）
- Kernel 内部：权重 unpack → 反量化到 **INT8**（而不是 FP16）
- 权重反量化走整数运算：`w_int8 = round(codebook_int8[indices])`
  - 或者直接存 INT8 码本（码本只有 2/4/16 个值，开销可忽略）

### 反量化（矩阵乘后）

- `out_fp16 = out_int32 * act_scale * weight_scale`
- per-token 激活 scale × per-group 权重 scale → 每个输出元素有独立的 scale
- 在 kernel epilogue 中完成（不写出 INT32 中间结果）

## 五、关键风险

1. **ppl 退化超预期**：INT8 激活量化可能对 MoE gate / attention score 敏感
   - 缓解：先只量化 MoE 内部 matmul（gate 保留 FP16），逐步扩大范围
2. **性能不达预期**：MoE 小矩阵吃不满 INT8 Tensor Core，收益被量化开销抵消
   - 缓解：P1 阶段先做 roofline 分析，确认计算 bound 再继续
3. **数值对齐复杂**：INT8 量化的舍入模式、截断方式影响对拍
   - 缓解：统一用 round-to-nearest-even，torch 和 Triton 都显式指定
4. **WxA16 迁移引入回归**：移动文件导致 import 错乱
   - 缓解：迁移后立即跑完整 WxA16 eval 验证，确保零回归
